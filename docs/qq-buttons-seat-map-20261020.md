# QQ 确认按钮与图书馆选座图核查

核查日期：2026-10-20。用户已确认按本方案实施。下面同时作为本轮实现和验收的规格；上线状态以文末实际证据为准。

## 官方能力

- [发送单聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)和[发送群聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)均有 `keyboard.content.rows`，可与 Markdown 同发。按钮支持跳转、回调、指令三类行为。
- 当前发送接口还定义了 `action.modal` 二次确认框，以及回调按钮的 `group_id` 互斥分组。这些客户端效果仍需实际 QQ 验证，不能代替服务端防重复执行。
- 指令按钮 `enter` 自动发送仅单聊可用，不能据此推断群里也会自动发送。旧 NodeSDK 文档不是当前客户端能力的完整依据。
- [Markdown 消息](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html)说明，2026-04-23 起单聊、群聊自定义 Markdown 向所有机器人开放。图片资源需可供 QQ 平台下载转存。
- [富媒体消息概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/rich-media.html)提供图片上传和 `file_info` 发送方式；本地文件可走分片上传。单聊和群聊的媒体资源不能直接混用。
- [互动事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/interaction_create.html)包含按钮数据、来源消息及操作者信息；[互动事件响应](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/interactions_interaction_id.put.html)的 ACK 只代表处理交互事件，不代表学校预约成功。

官网部分不存在的路径会以 HTTP 200 返回“启动接入”。本次核查逐页确认标题，未把这些兜底页当成接口文档。

## 当前系统证据

线上 LangBot QQ 适配器已有 `send_markdown_keyboard`、图片上传及发送能力。按钮收取分支目前服务于 Dify 表单，普通插件的 HENU 确认卡没有自动接入该分支，不能仅在提示词中写“显示按钮”解决。

只读调用学校 `/v4/Space/map`，区域为金明校区 701 七层南自习室。返回包含 `web_plane`、`map` 和日期配置。原始图片为 1366×768 的静态底图，不能直接用底图绿色表示实时可用。

进一步只读调用 `/v4/Space/seat`，证实返回座位号、百分比坐标、宽高、状态和状态名称。实际样例中 `1/空闲` 与 `2/已预约` 并存。按这些数据重新绘制 4096×2560 PNG，保留学校座位相对位置、明确标出空闲、已预约、使用中、不可用、未知，并显示完整日期时段和查询时间。未返回的门窗、入口和走道不补画。它是按学校数据绘制的座位图，不称为网页截图。

学校坐标是手工框选的数据，直接放大会显示歪斜。绘制时只对小于约半个座位的微小坐标偏差对齐，同排同列对齐、座位统一尺寸；保留更大的间隔及区域形状，不按座位编号重排物理位置。

私有运行证据保存在服务器备份目录的 `seat-map-capability.json`；不提交账号、Cookie、聊天身份、完整响应或占座人员信息。区域地图不等于指定时段的可用座位，仍须结合 `/v4/Space/seat` 的实际时段结果。

## 接入后的用户流程

1. 查询图书馆：直接展示各校区、各区域余座，区域名称可选。
2. 选区域和日期、起止时间；已有明确时段则直接沿用，不额外重复追问。
3. 展示区域名称、完整时段、查询时间、高清座位图、该时段余座与已预约数量。图上显示座位号，下方提供少量可用座位按钮及刷新入口；也可输入“选座 号码”，不为数百个座位各生成一个按钮。
4. 选择座位只生成预约预览，展示校区、区域、日期、时段、座位号，并提供“确认预约”“取消”。
5. 本人点击确认后再次检查可用性；学校返回预约成功和记录后才显示成功。座位已被占用时刷新选择，不自动换座。

使用学校真实页面截图时应称“页面截图”；按学校底图、位置和实际座位状态生成的图应称“座位图”，不能把生成图称为截图。图片和按钮不能暗示图中任意位置本身都支持点击选座。

## 确认接入约束与验证

- 按钮携带一次性的不透明操作引用，服务端绑定用户、机器人、会话、原卡片、具体操作和有效期。不能让旧按钮去确认“当前最新待办”。
- 校验、持久化消费、防重复提交沿用现有确认流程；确认与取消互斥，过期或重启后旧卡片不能恢复执行。
- 校园账号凭据仍仅在私聊处理。按钮回调不经模型解释为另一个操作，不绕过现有来源校验。
- 普通查询和选座不写学校预约记录；地图失败则保留文字余座与座位号选择，不伪造可用状态。
- 需覆盖：他人点击、跨会话、旧卡片、新操作替换、过期、重复与并发点击、取消后确认、重启、时段不一致、座位被抢、图片发送失败、文字回退。
- 接入阶段仍须分别完成插件测试、实际 SDK/宿主适配测试、部署、真实 QQ 按钮点击和收图验收。真实预约提交需要用户明确确认具体预约。

## 本轮约束

- 交互首版仅在私聊接入，群聊原有公开查询保留；不能从群按钮访问个人预约。
- 旧的校园写操作确认采用原来的持久化确认引擎，按钮精确对应原令牌。HENU KIT 网站绑定仍保留原有引用授权校验，不接通一个绕过引用的新确认路径。
- 沿用已约定的测试边界：对外卡片和消息处理、CLI/API 请求及实际 SDK/QQ 适配器。测试中的学校接口为模拟；实际学校操作只发只读查询。
- 用户明确要求：上线后的 QQ 验收到生成预约确认卡片为止，**不得点击“确认预约”或提交真实预约**。可以验证取消当前待确认预览，不取消学校已有预约。
- LangBot 交互接入仅作用于 LangBot 交付分支；独立 MCP/Agent Skill 的业务接口和提示词不作变更。
