# QQ 校园 Agent 对话迭代

## 目标和测试边界

用户指出校园 Agent 被做成了固定脚本，要求设计样例、测试、调整并继续迭代。本轮以 `1dfe4f600c5cf3fb320852a7f8961c919ea7b989` 为起点：自然语言由 Agent 理解和选择工具，完整条件不再走菜单，缺信息才追问，中途改口沿用未改变的条件，同一轮可以完成多项必要只读查询。菜单继续作为快捷入口；身份隔离、真实数据和最终本人确认仍由程序保证。

沿用已同意的消息处理、工具 CLI/API 和真实 SDK/QQ 测试边界。预约测试只生成预览，不点击确认，不提交学校预约，不改账号或既有预约。

## 复现和修复

QQ 原请求“帮我看看明天有没有课，再查一下金明图书馆各处还剩多少座位，先不预约。”只显示课表第1/2页。消息边界回归测试先失败：两个工具结果的固定卡片覆盖了 Agent 综合回答和追问。

- 成功的查询结果允许 Agent 综合回答，固定卡片仍用于精确菜单、空回答兜底、失败和最终操作确认，不将模型文字替换掉确认卡。
- `reply_text` 和 `next_commands` 是事实摘要和工具参考，不再要求逐字复述或每步等待菜单选择；模型可以连续完成当前目标需要的只读工具调用。
- 工具参数示例统一 LangBot 空格方言，图书馆开始时间用 `--time`，区域ID用 `--area-id`。不增加自然语言正则分支代替模型判断。
- 最近5分钟、当前本人私聊的图书馆菜单条件只进入本轮临时系统上下文；模型可理解“时间不变”等追问，用户新条件优先。身份、按钮引用、确认令牌不进入该块；过期或其他用户不继承。真实 `PromptPreProcessing` 在支持的SDK中没有发送者字段，因此通过当前查询的认证身份变量定位上下文。

## 真实模型样例

`ops/evaluate_qq_agent.py` 是可重复的隔离评测器，调用线上同款 `deepseek-flash`，使用实际工具声明、CLI解析和结果摘要。只有合成课表、区域和座位数据；不连接学校、不加载用户账号、不调用真实确认引擎。不是上线的对话流程。

| 样例 | 验收点 |
| --- | --- |
| 同时查明天课表和金明余座 | 同一条回答完成两项，不掺其他校区，不分页隐藏第二项 |
| 给全区域、日期和起止时间 | 直接查座位，不重复问校区、楼层或时间 |
| “换成明伦，时间不变” | 校区更新，日期和起止时间保留 |
| “先不查座位，我后天有什么课” | 切换课表工具，不继续旧选座流程 |
| 查询靠窗、有插座 | 有空座结果，无属性数据时不猜 |
| 订明天座位但没有时间 | 补问必要时段，不生成不完整预约 |
| 以前绑定过，查看状态 | 查状态，不要求重绑或重新发送密码 |
| 只看002预约预览，别替我确认 | 保留完整时段，不提交、不代确认 |
| 给全条件查空教室 | 正确校区、楼栋、教学周、星期和大节 |

固定样例在本轮冻结校园时间为2026-10-20，评分检查工具参数和关键事实，禁止未知操作。旧配置 **4/9**，候选 **9/9**；早期探索时的评分口径校准不作为前后对比。证据：[旧配置](evidence/agent-baseline-20261020.json)、[候选](evidence/agent-candidate-20261020.json)。模型有随机性，不将一次通过当作普遍保证，继续用QQ实收验证。

本地回归 **593通过**；真实Python3.12/SDK0.5.8相关回归 **92通过**，包含新增的综合回答和菜单上下文测试。未修改独立MCP与Agent Skill目标。本轮只在现有LangBot生产覆盖层上按差异移植，不覆盖原有凭据保护、确认引擎、订阅提醒、来源处理或其他插件。
