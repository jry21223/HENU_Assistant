# 手机新确认卡被拒绝的对照验收

用户同意在手机／平板上只点击“取消”，禁止实际预约提交。

## 对照结果

15:47 在当前线上版本生成全新确认卡：金明 701 南自习室，2026-10-21 08:00–23:00，002号。已只读确认待预约内容完全匹配，卡片有效至 15:52。

用户反馈手机端首次点击灰色“取消”仍提示“无权限”。随后在同一张卡的有效期内用 Mac QQ 点击取消成功，收到“已取消，本次没有提交。”，只读确认本人待确认已清空。这证明前一轮修复的旧卡错误分类，并未解决手机端新卡的兼容问题。

## 本轮单项对照

发送给当前私聊收件人的键盘，客户端权限描述从 `type=0 + specify_user_ids` 改为 `type=2`。仅改变客户端点击描述，**实际执行授权不变**：

- 发送接口拒绝将交互卡发送到群聊或另一个收件人。
- 回调继续校验实际用户、私聊场景、原卡片、按钮引用、有效期和整组一次性消费。
- 插件继续验证本人会话、精确操作和确认令牌；别人即使能点转发的卡片也不能执行。
- 不修改账号绑定或校园权限，不改变确认／取消样式，不提交真实预约。

同时保留最小回调诊断：只记录固定的接收／拒绝原因名称（用户、场景、消息、按钮、未知、超时、已使用），不记录任何消息内容、身份、按钮引用或令牌。这样可以区分客户端拦截和服务端拒绝。
