# 选座只在确认时显示按钮

用户要求：选座界面不显示按钮；仅确认时显示按钮，并用强调色区分；核对 QQ 能否直接点击座位图选座。沿用此前允许上线与 QQ 验收的范围，预约仅到预览，不提交。

## QQ 能力核查

- [发送单聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)的 `RenderData.style` 定义：0 灰色线框，1 蓝色线框，3 白底红字，4 蓝底白字。首轮按文档使用 4，但实际 Mac QQ 将其渲染成灰色。最终确认使用已实测可显示蓝色强调的 1，取消使用 0。
- [Markdown 图片](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html)仅定义图片资源和显示大小；[互动事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/interaction_create.html)定义按钮 ID、按钮 data、操作者及消息来源，没有图片热区或点击坐标。因此现有官方消息协议没有提供聊天内按图片坐标选座的接口；不把普通图片宣称为可点击座位图。
- 网页或小程序可以实现真正的点选座位，但属于另一种界面和会话授权接入，不能把发送一张图片等同于已经实现。已向用户询问是否采用 QQ 内网页；本轮先完成独立的原生聊天改动。

## 行为与测试边界

1. 图书馆查询仍直接返回真实余座；校区、楼层、区域、学校时段均用文字选择，支持当前清单的序号或名称。
2. 座位图下不显示座位、换一批或刷新按钮。看图回复 `002` 或 `选座 002`，回复 `刷新座位` 重查。图片发送失败时保留空闲座位号作为文字回退。
3. 只有精确预约预览带“确认预约”“取消”，分别为蓝色文字/描边和灰色描边。保留本人、机器人、会话、具体操作、原卡片、有效期和整组一次性消费；确认与取消不可同时执行。
4. 文本选项仍绑定当前本人会话；其他查询不被当成选座，跨用户和失效状态不接受。不会自动扩大预约时段。
5. 沿用卡片/消息入口、实际 QQ 发包与学校请求边界测试；线上 QQ 验收只到确认页，然后取消预览，禁止真正预约。
