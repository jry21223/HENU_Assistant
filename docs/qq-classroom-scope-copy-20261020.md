# 空教室跨校区匹配与回复文案

## 问题与复现

QQ 实际对话：找自习室 → 金明 → 综合教学楼，返回“暂无可核验结果”。线上查询缓存显示请求到了金明校区的楼号 `0003`；该楼号实际来自明伦“综合教学楼”，金明综合楼1的楼号是 `0006`。

直接调用生产旧版本 `resolve_resource('综合教学楼', resource_type='building', campus_code='02')`，返回明伦楼栋与教室，断言失败。原因有两处：registry 精确别名分支未筛选校区和类型，错误候选还会占满数量限制；resolver 的文本拆解结果没有最终作用域检查。这些保护已存在于当前发布分支源码，但旧生产覆盖层未同步。

## 修复

- 使用 `ops/qq_classroom_scope.py` 对旧生产模块作小范围补丁：精确别名先筛选类型、校区、楼栋；resolver 返回前再次筛选类型和校区。保留生产两个模块其他代码。MCP、Agent Skill 工作区未改。
- “综合楼／综合教学楼”有多栋时，列出所选校区实际楼名；回复序号后用明确校区和楼号查询，不猜测第一栋。自动确定的大节也在选择期间保留。
- 选择仅接受有长度上限的 ASCII 数字，不吞其他消息。状态继续按 bot、会话类型、会话、发送者隔离，五分钟过期。
- 卡片省去“已完成”“服务回执”和“下一步”标题；空教室直接显示时间地点、教室名与座位数，简短说明临时占用以现场为准。关键失败、过期与待确认状态保留。
