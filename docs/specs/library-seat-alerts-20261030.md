# QQ 图书馆空位提醒

用户确认：支持一个区域或一个指定座位；有位后继续监控，后续再次放出也提醒。
用户要求低频检查，每5或10分钟一次；默认10分钟，仅允许5或10分钟。
测试边界：QQ设置入口、后台查座到私聊通知。

- 私聊发送 `空位提醒帮助`，使用 `设置空位提醒 日期 "区域名称或ID" 开始 结束 [座位号或全部] [5或10]`。
  日期支持今天、明天、YYYY-MM-DD。省略座位表示整个区域，省略间隔为10分钟。
- 每个Bot与QQ用户保存一个提醒；已有活动提醒需先取消，再设置。
- 以实时学校区域列表确定唯一区域ID；特定座位保留学校原始座位号。
- 按完整日期和起止时间查询。当天余座、未知、失败、缺失座位均不推断为空位。
- 首次发现空位及后续新增空位提醒；同一座位持续空闲不重复提醒。
  必须观察到座位明确变为非空闲，才允许其再次空闲时提醒。
  未知响应、网络失败和缺失座位保留原有观察状态，不能造成重复提醒。
- 一轮新增多个空位合并为一条纯文本QQ私聊通知。查看和取消均按Bot与QQ隔离。
- 提醒持续到使用开始时间；过期、取消后不再查询或通知。
- 后台只使用当前QQ已保存的图书馆登录态，不调用登录或提交密码。
  固定当前校园主体和登录态指纹；账号、会话变化或登录失效时暂停，提示手动查座后重新设置。
  兼容未带主体标记的历史会话，依赖现有重新绑定会清除旧会话的约束；不补写主体元数据。
- 查询和通知不持有全体提醒的注册表锁；通知前再次核对取消、替换和过期。
- 每轮检查先持久化下次检查时间，重启不缩短5/10分钟间隔。
  通知前持久化去重状态；发送结果不确定不自动重发该批空位，后续新空位仍可提醒。
- 只增加LangBot QQ能力，MCP和Agent Skill不提供后台QQ通知；普通预约行为不变。
- 发布前运行全量pytest、静态检查、独立Standards和Spec审查；生产部署与真实QQ接收验收单独记录。
