# 教务成绩与绩点查询

## Problem Statement

用户希望把 sin0317/henu-cli 的成绩与绩点查询接入现有校园助手，直接在自己的 QQ 私聊或独立 CLI 中使用。现有课表、空教室与选课能力没有成绩查询入口；不能把此前源码调研称为已接入。

## Solution

首批提供 `grade list` 和 `grade gpa`，只查询当前绑定校园账号的入学以来、有效、主修成绩。延续既有 QQ 私聊、Storage 隔离与公开 CLI 验收入口。读取学校实际表单并校验主体、查询口径及页面结构；无法识别时明确失败，不编造成绩、绩点或“没有成绩”。

## User Stories

1. 作为已绑定用户，我希望在私聊中查询自己的成绩，以便了解每门课的成绩与已获学分。
2. 作为用户，我希望查询平均绩点和加权平均成绩，以便区分两种指标。
3. 作为用户，我希望知道绩点来自学校汇总还是明细重算，以便正确理解其含义。
4. 作为用户，我希望未知数值保留未知，以免被误报为挂科或零绩点。
5. 作为用户，我希望等级制成绩保留原文，并仅在学校提供数值绩点时参加相应计算。
6. 作为用户，我希望读取所有学期的成绩表，避免只得到第一张表。
7. 作为用户，我希望学校分学期小计不会冒充全范围总计。
8. 作为用户，我希望分页查看明细，避免长成绩单在聊天摘要中被无声截断。
9. 作为用户，我希望登录失效、账号不符与真正空成绩有不同提示。
10. 作为用户，我希望群聊请求在读取个人数据之前被拒绝。
11. 作为用户，我希望两个 QQ 的成绩与登录会话互不混用。
12. 作为维护者，我希望保留上游 MIT 署名及固定来源版本，明确移植边界。

## Implementation Decisions

- 第一批是 LangBot 插件和使用同一业务实现的独立终端；MCP-server 与 Agent Skill 分支没有该入口，明确记录交付差异。
- CLI 使用空格方言；提供成绩明细分页与绩点视图，拒绝不认识的参数，不能通过参数指定另一个学生。
- 使用既有青果校园客户端和当前聊天身份的保存会话。读成绩本身不自动提交密码、不保存新账号、不修改学校业务数据。
- 严格核对当前登录主体后，按合法同源导航和实际表单查询。表单字段从已核实页面读取，限制 HTTPS 官方域名、查询路径和查询口径。
- 不直接执行上游全局 Node CLI，不共享其单用户浏览器 profile 或成绩缓存。
- 学校明确且覆盖全部明细的汇总优先；否则按有明确数值绩点、已获学分的明细重算，注明范围和缺失项，不硬编码百分制转换。
- 不擅自定义重修去重规则，使用学校“有效成绩”的筛选口径。
- 保留来源、查询范围与获取时间；本阶段不新增持久成绩缓存或诊断原始成绩 HTML。
- 按 MIT 保留 henu-cli contributors 版权、完整许可文本及来源提交。

## Testing Decisions

- 延用此前已约定的 `HenuCliSafe.call` 公开入口，测试真实 CLI 参数、私聊约束、账号隔离、结果与展示；仅替换外部学校 HTTP、时钟与测试 Storage。
- 一次一个红绿切片；样例期望由独立合成成绩单给出，不按实现重新计算期望。
- 覆盖多表成绩、汇总列序、未知学分、等级制、零学分、缺失绩点、分学期小计与总体不符、表头变化、登录失效、主体不符及禁止群聊。
- 真实账号只读验收继续使用已有授权与隔离会话，独立核对学校汇总；不把模拟 HTTP 测试称为真实查询。
- 源码测试、PR/CI、线上部署和真实 QQ 验收分别报告。本轮功能实现不等于已更新线上插件。

## Out of Scope

毕业学分核对、专业培养方案、ICS、图书馆借阅，以及任何选课/成绩修改；朋友雨课堂执行器的源码部署。
