# 定时预约合并后安全修复（2026-10-26）

## 核实范围

基线为 `langbot-plugin` 的 `b81ec8b`，已包含 #65、#66、#67。
#66 修复无人值守校园重新登录，#67 修复河宝 OAuth；二者没有修复 #65 的两项 P2。
原调度器在全局异步锁内等待完整学校请求，底层还通过
`_run_in_user_storage` 在全局线程锁内切换用户路径并访问学校。
持久化 `attempting` 后发生进程退出或最终状态写入失败，会永久占用活动计划槽。

## 最终行为

- 扫描仅在锁内读取注册表和启动每用户独立任务；后台每15秒继续扫描，不等待学校请求。
  同一插件实例的协调器共享任务表与锁，重复扫描不会重复启动用户任务。
- 每个任务独立核验当前 QQ 绑定、终身会员及校园主体；重新读取并比对原计划后，
  持久化一次性执行标记，再允许学校请求。存储写入抛错时不访问学校。
- 学校请求使用独立客户端、空密码、已有图书馆 Token 和显式用户文件路径，
  不使用切换全局用户路径的线程锁。Token 失效不走 CAS 或密码登录。
  保留每请求25秒超时、完整预约时段、提交前90秒截止和 `max_attempts=1`。
- 完成后在短锁内重读注册表，只更新匹配执行标记的计划，保留其他用户的并发变更。
- `attempting` 永不自动重试。本人私聊查询“自动预约状态”后可看到解除码；旧版本遗留
  的执行标记在查询时补充解除码。用户须先核对学校预约记录，再独立发送
  `解除自动预约 <解除码> 已核对`，通过本人、Bot、消息来源和两分钟时效校验后解除。
  活动任务仍在运行时拒绝解除。跨用户、跨 Bot、错误或旧解除码均拒绝。
- 解除仅将本地槽标为 `released_unknown`，不表示学校失败，不取消学校记录，
  不重试旧计划。新计划仍须重新鉴权、设置并确认。扫描调用者取消不会取消活动学校请求。

## 模拟验证

回归覆盖：慢请求期间另一用户完成和下一次扫描、状态查询不阻塞、协调器重复扫描、
重启后旧标记恢复、活动任务禁止解除、取消扫描、鉴权期间取消、过期窗口、
执行标记写入未应用/已应用但回执丢失、最终结果写入失败/回执丢失、解除身份与消息
时效校验、隔离客户端并行及用户 Token 隔离、学校提交响应超时且只提交一次。
所有学校边界均为模拟；未进行真实校园预约。

## 发布与验收边界

当前只支持单活动插件进程；不同进程/主机共享存储时尚无原子 CAS/租约，不能多实例调度。
部署必须先暂停新计划并等待活动请求结束，备份线上源码和计划注册表，读取线上差异，
以增量 overlay 保留既有安全热修、私有环境和用户数据。不能直接用整包覆盖生产。
回滚时保留执行标记和已解除记录，不能恢复旧注册表使学校提交被再次执行。
