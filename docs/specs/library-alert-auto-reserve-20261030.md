# 空位提醒设置时授权自动预约

用户明确：仅 HENU-Kit 终身会员；在设置空位提醒时询问是否有位后自动预约。
授权发生在设置阶段，后续检测到所选区域或指定座位可用时直接提交，不再临时询问。
普通提醒继续开放，普通手动预约和原有定时预约的权限、流程不变。

## 用户流程

1. 设置区域或单座位、日期、完整使用时段与5/10分钟间隔后，先开启仅提醒，并询问是否开启自动预约。
2. 选择自动预约后核验当前 QQ 的 Kit 绑定、终身会员和有明确归属的已有校园会话。
3. 展示准确的地点、日期、完整时段、座位范围。区域模式授权在该区域选择一个符合条件的空座；单座位模式不替换座位。
4. 本人在另一条有效消息确认后才启用。确认前不预约，取消或保持仅提醒会撤销未执行的预约授权。
5. 按原频率检测，不额外提交密码。已有空位也可在下一次正常检查时触发。
6. 一次成功后结束任务。结果未确认或提交失败时停止，不自动重试，提示核对学校预约记录。

## 执行约束

- 执行前重新核验会员、同一 Kit 用户、同一校园账号及会话指纹；资格或登录态变化时暂停。
- 持久化一次性提交标记后才允许学校预约请求。写入失败或回执不确定时不访问学校。
- 查询、鉴权时取消优先；已开始的请求不能被“取消提醒”表述为已撤销学校预约。
- 学校请求使用空密码、saved-session-only、精确日期时段、一次尝试和提交截止时间。
- 进程重启、重复扫描、按钮重放和同一消息重放均不重复提交。
- 不给旧 Token 猜测或补写账号归属。保留生产已有可信登录归属链；源码补齐对应的归属过滤及保存。

## 验证

沿用 QQ 消息/SDK 和后台 tick→学校 HTTP 的公开边界。覆盖设置、独立确认、区域/单座位、非会员和鉴权异常、账号变化、取消竞态、持久化异常、超时和重启后的单次提交。
所有学校请求使用合成边界；真实 QQ 只验收设置、授权展示和取消，不占用学校座位。

## 发行范围

仅 LangBot QQ 发行目标。会员校验、消息授权和后台任务均为该目标独有；MCP/Agent Skill 不增加空位预授权预约。LangBot 的 server facade 同步生产已存在的账号归属过滤/保存，避免新安装复用无归属会话；不在此轮修改另两份发行副本，其源码归属校验差异需独立核对，不能推定已同步。

## QQ 原生按钮来源验收修复（2026-10-31）

真实 QQ 点击进入了消息来源错误，文字入口可以正常进入终身会员授权预览。已用实际宿主桥接和 SDK 序列化复现：原生按钮生成的消息只有 Plain，没有普通聊天消息的 Source，虽然事件本身有时间。

保持宿主原有回调和回复路由。在插件验证当前人、Bot、会话、独立轮次、按钮时效并消费同卡按钮后，签发仅内部传递的不可变动作回执，绑定原动作句柄、当前轮次、所属身份、原到期时间和准确参数指纹；预约控制再次核验回执，用不同按钮句柄作去重来源。普通文字入口仍必须提供真实、未过期的 Source；不为无来源文字补造凭据，也不采用通用跳过校验开关。
