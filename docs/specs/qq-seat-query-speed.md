# 座位查询耗时优化

基线：`5bc2bb1`源码，线上`0f50250`业务代码及已保留的原子资源索引覆盖层。目标是减少完整座位查询的等待，保留Agent、原业务卡、高清坐标图、占用状态、本人隔离及确认校验。

## 测量与范围

Mac QQ历史工具耗时64.959秒。相同账号现有token的只读复现、生产公开索引的私有副本测得：学校HTTP总3.325秒，索引更新47.800秒，4096×2560制图0.907秒。对5条资源的小样本profile确认主要时间用于重复编码完整JSON快照。仅采样现有token查询，不尝试重新登录，不提交预约；性能脚本不改生产索引。

修复将一次座位结果的资源元数据、别名和来源映射在原有锁及原子快照中批量合并，避免每个座位都重读重写2MB索引。既有单条写入仍保持相同语义；多进程／线程和同时读写不能丢记录或产生部分索引。异常时不能提交半批；损坏的权威快照仍拒绝写入。空座、占用、时段和坐标仍取本次学校接口，不放宽缓存或确认。

本地发行源码的registry还是旧的分文件实现；优化前须带回当前生产已在使用的原子registry及其写文件依赖，不能在发布时用旧实现覆盖生产。发布只移植本次批量方法和调用点，保留其他覆盖层；不迁移／恢复用户数据库。仅LangBot发行目标，本次不修改独立MCP／Agent Skill工作区。

## 已有测试边界与验收

沿用已同意的公开CLI／工具API、消息／SDK及QQ边界。离线学校HTTP返回固定41席（40空闲、1预约），公开library_query必须保留完整结果与资源解析；以大索引编码总量预算捕捉逐席全表编码。补充批量索引公开接口的并发、别名替换、异常原子性和损坏状态保护。使用生产同SDK副本测量并回归，不以合成测试代替QQ实收。

相同区域、日期和时段上线后由QQ自然语言查询，确认业务卡和高清图真实送达，并读取对应工具和整轮耗时；不使用短期缓存命中来代表冷查询性能。不实际预约、不改绑定、不取消既有预约。PR #59保持打开。

## 实现与发布前证据

逐席写索引改为`upsert_resources`，整批共用原锁、只读写一次快照；清理受影响别名及来源映射只扫描一遍，重复资源沿用最后一次出现的顺序。原单条接口继续共用相同实现。生产的原子IO与进程锁带回发行源码作为既有兼容基线，发布时不覆盖它们；发布实际只改registry存储、registry入口、导出和`server_impl`共4个文件，其余146份生产Python保留校验和。registry搜索及校区筛选差异逐函数对账保留，未用本地整文件覆盖线上。

另修复生产覆盖层中`_load_library_cookies`误过滤`_v4_token`的问题：仍先校验缓存的`_subject_student_id`与绑定主体相同，之后才保留v4令牌；其他内部元数据仍过滤。原有过期校验、重新登录和失败处理不变。可审计补丁是`ops/qq-library-cached-token.patch`，仅适用于含该主体校验的生产覆盖层，本地原读取实现本已保留该令牌，不强行应用。

这是现有token查询和生产公开索引私有副本的单次测量，不是QQ全链路耗时或延迟保证。采样只走pick、map、seat等白名单只读接口，未尝试登录或改生产索引；修复候选整批约0.1秒满足索引≤1秒反馈门槛。第一版批量仍逐资源扫描别名，测得1.1116秒未达门槛，故继续合并扫描。

公开工具回归先观察到40席编码约87–88MB、超过8MB预算而失败；修复后通过，末席资源仍可按别名查到，占用席位仍保留于图像快照。新增并发混合单条／批量、重复别名、异常改名提交和损坏快照保护。生产SDK原子索引10项既有回归亦通过。

最终本地643项通过；生产Python3.12／SDK0.5.8相关125项通过，构建、编译及Standards／Spec双轴复核通过。扩大到另外68项仓库测试时有42项失败，使用同一测试逐项对照生产原文件副本与候选，结果完全相同、零新增失败；这些历史偏好、绑定、认证、预约参数和空教室契约差异未在本次速度优化中机械修改，也不声称生产全套全绿。私有部署目录保留JUnit与差异清单。
