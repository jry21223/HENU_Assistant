# 旧按钮被误报为没有权限

## 已核实的问题

用户提供的 15:01 手机端截图显示：楼层卡片下已经有区域卡片，再次操作楼层按钮时出现 QQ 的“无权限操作”。截图属于仍有楼层按钮的旧版界面；新版选座阶段已改为文字选择。

截图本身不能确认具体点击了哪个按钮，也没有留存那次完整的原始回调。已询问是否是在选过楼层后再次换楼层；不把这一推断写成已证实的手机身份不符。

可以确定的代码问题是：宿主将按钮已使用、过期、重启后缓存不存在，以及真正身份／来源不符，统一返回 ACK `code=4`。[QQ 官方互动响应](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/interactions_interaction_id.put.html)定义 1 为操作失败、3 为重复操作、4 为没有权限。原回归复现：本人的有效点击第一次 ACK=0，第二次 ACK=4；预期应为 3。

## 修复范围

- 保留已有绑定的五分钟有效期和最多 2048 条容量，整张卡第一次使用时在任何 await 前标记已使用；本人重复点击或再点同卡其他按钮均 ACK=3，不重复执行。
- 过期、已被清理或宿主重启后未知的卡片 ACK=1，不再误报账号没有权限。
- 真实用户、会话场景或来源卡片不符继续 ACK=4。发送端仍限定原用户，服务端身份校验和插件精确操作确认都不放宽。
- 不改账号绑定、校园权限、校历、提醒或任何学校预约记录；不恢复选座阶段的按钮。旧卡片失效后应重新查询，不能以重新绑定来解决。

## 验证

回归先红后绿，覆盖本人重复点击、同卡兄弟按钮、过期、未知及他人点击；整组只入队一次。部署和最终检查记录在本轮结束后补齐。手机截图那一次的具体触发条件仍与上述确定问题区分记录。
