# LangBot 原生配置热重载

线上 SDK 的旧插件在原生配置保存触发的 `RESTART_PLUGIN` 内重新注册时，
获取设置的 RPC 继承了控制桥的安装标识，导致 Core 拒绝并使插件停留在未初始化状态。
补丁显式传入当前插件受信的工作区上下文，完整安装绑定路径及安全校验保持不变。

`legacy-reload.patch` 基于 2026-10-24 线上 SDK 冻结源码提交 `69431b9`，
修复提交为 `6ef194e`。它不是对任意上游版本的通用补丁，应用前须核对源码。
运行镜像基线为 `090ace38345b078945c3d490deb1c5cea57300518143df7beee79d6c5dfdbd7b`。

公开启动/注册链的五项断网回归覆盖冷启动、配置重载、跨工作区、过时代次及缺少绑定。
回归只模拟进程与外部 Core RPC，不写业务知识库，也不使用校园账号。

上线采用基线镜像上的单文件层，保留 HENU 已有兼容补丁、其他插件、主服务及 Box。
原生验收使用相同配置执行一次保存，随后只读轮询插件恢复；同时确认所有插件均 initialized、
配置相同且三个容器的启动时间未变。失败先对账，不重复提交配置保存。

回退需要恢复部署前 HENU 九个源码文件和 Compose 中原运行镜像，再仅重建插件运行容器。
知识库、机器人、流水线和用户数据不参与回退写入。
